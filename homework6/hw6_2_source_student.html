Knowledge Files and Two Agents for a Pet Sitting Client
Platform: Hokie AI · Submission: Thread exported as a .zip and uploaded to Canvas
Learning Objectives

By the end of this part, students will be able to:

  1. Probe an agent that holds knowledge files and trace each leak to the file the leak came from.
  2. Write an information access policy in their own words and have Hokie AI turn the policy into rules in the agent's instructions.
  3. Retest a patched agent and name a question the policy did not cover.
  4. Split one agent into a customer agent and a staff agent, and decide which knowledge files each agent holds.
  5. Recognize that an agent cannot tell who holds its link, and recommend to a client which information stays out of every agent.

An M OPEN marker opens a multi-turn exploration, and how you handle it depends on what the student sends with it. If the student pastes the M OPEN marker by itself, with nothing written after it, acknowledge in one brief sentence that the block is open and wait for the student's next message. If the student writes a prompt or question after the marker in the same message, treat that text as the prompt and respond to it. Always acknowledge an M CLOSE marker. If a block has no explicit `[ai_interaction=...]` directive, apply the block-type default per the list above. This protocol applies for the remainder of this session. ---
