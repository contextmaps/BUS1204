Two Agents and a Manager on One Sheet
Duration: 75 minutes · Platform: Hokie AI, Google Sheets and Google Apps Script · Submission: Your reflection thread, exported as a .zip and uploaded to Canvas before leaving class · Lecture Mode: consolidation
Learning Objectives

By the end of this lecture, students will be able to:

  1. Ask Hokie AI for a short script that lets agents add, list and decide requests in a Google Sheet, and read what each line does.
  2. Give a customer agent a tool that adds a request, and prevent it from reading other customers' requests.
  3. Give an office agent tools that list requests, check live data and record a manager's decision only after the manager confirms.
  4. Explain why the manager, and not an agent, approves or declines each booking request.
Section 1 of 4
INTRODUCTION
📋 Note for Students

Today you finish the Kestrel Bend system. The customer agent, Kestrel Bend Seat Check from the last class, takes a booking request and writes it in the sheet. This page calls it Seat Check. A second agent, the office agent, helps the manager see the request, check the seats and the weather, and record the decision. Then your team turns to its own project.

At Kestrel Bend, a customer asks Seat Check for four seats on the sunset paddle. Seat Check cannot promise them, because the manager decides every booking. So Seat Check writes the request in the business's sheet, and the office agent helps the manager decide. Today you build that system on your Kestrel Bend sheet from the last class.

The system has four parts. The customer agent, Seat Check, reads the Trips tab and adds each request as a pending row in the Requests tab AND the Requests tab holds one row per request, with its status and the manager's note AND the office agent lists the requests, checks the seats and the weather, and records the manager's decision AND the manager is the person who approves or declines every request and updates the seats. Four parts.

Seat Check can add a request, and it does not have a tool for reading requests. Only the office agent can read them, so one customer never sees another customer's booking.

Class material
The script prompt
Write a Google Apps Script for a Google Sheet that two Hokie AI agents call through API Calls. Follow these rules exactly.

The sheet has a tab named Requests. Row 1 holds the column names. Read the column names from row 1, so the script works whatever the other columns are. Four of the columns are always there: request_id, time, status and manager_note.

At the top, put the office key in a constant named OFFICE_KEY with the value otter-office-2741.

Write one function named doGet(e). It reads the values in e.parameter and does one of three things, depending on the value of action.

1. action is add. Add a new row at the bottom of the Requests tab. Fill every column whose name matches the name of a value that was sent, and leave the other columns empty. Set request_id in two lines of code. In the first line, add 100 to the number of rows in the tab before the new row is added, and keep the result as a number. In the second line, put the letter R in front of that number. A tab with three rows gives R103, never R3100, R1003 or R3. Set time to the current date and time, and status to pending, whatever was sent. Reply with ok true, the request_id and the status.

2. action is list. Do this only when key equals OFFICE_KEY. Reply with ok true and a list named requests that holds every row after row 1, each as a record of column name and value. If a status was sent, include only the rows with that status.

3. action is decide. Do this only when key equals OFFICE_KEY. Find the row whose request_id equals the request_id that was sent. Write the status that was sent in its status column, and the manager_note that was sent in its manager_note column, or empty text if no manager_note was sent. Reply with ok true, the request_id and the status. If no row matches, reply with ok false and the error no request with that request_id.

If key is missing or wrong for list or decide, reply with ok false and the error office key missing or wrong, and change nothing. For any other action, reply with ok false and the error unknown action.

Send every reply as JSON with ContentService and the JSON MIME type, through a small helper function named reply.

At the end of every line of code, write a short comment in plain English that says what the line does, for a reader who has never programmed. Give the whole script in one code block, with nothing after it.
Paste it into a new regular Hokie AI thread. Change nothing.

What add_request sends, field by field

action      Always the word add. The script adds a new row when it receives add. The enum allows only that one value.
name        The customer's name. The script writes it in the name column.
trip_id     Which trip, such as KB104. The agent takes it from read_trips, and the script writes it in the trip_id column.
people      How many people, as a whole number (integer). The script writes it in the people column.

Now run the whole loop, in five steps. After each step, look at your Requests tab.

First, make a request as a customer. Start a new thread with Kestrel Bend Seat Check and send the booking message below. Answer its questions, and when it repeats the request, reply yes. Seat Check gives you a request_id, and a pending row for Sam Patel appears in your Requests tab.

THEN act as the manager. Start a new thread with Kestrel Bend Office and send manager message 1, then manager message 2. The office agent lists the pending requests and compares Sam Patel's 4 people with the seats left on the trip.

THEN ask about the weather with manager message 3. The office agent calls get_forecast and reports the chance of rain and the high temperature for each day.

THEN decide. Send manager message 4, with the request_id Seat Check gave Sam Patel. The office agent repeats the decision and asks you to confirm. Reply yes. The Sam Patel row changes to approved with your note, and the agent reminds you to lower the seats.

THEN update the seats. On the Trips tab, click cell H5, the seats left for KB104, and change 6 to 2. Start a new thread with Kestrel Bend Seat Check and send the last message below. Seat Check now says 2 seats, so a group of 4 does not fit. The agent may take a minute to see the change.

In this loop the office agent gathers the facts, and the manager makes the decision. The manager answers to the customer and to the business for every booking. The manager can also weigh what the sheet does not show, such as a phone call with the customer or a guide who is out sick.
