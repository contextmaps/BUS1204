A Script for the Business's Sheet and the Customer Agent
Duration: 75 minutes · Platform: Hokie AI, Google Sheets and Google Apps Script · Submission: Your reflection thread, exported as a .zip and uploaded to Canvas before leaving class · Lecture Mode: consolidation
Learning Objectives

By the end of this lecture, students will be able to:

  1. Ask Hokie AI for a short script that lets agents add, list and decide requests in a Google Sheet, and read what each line does.
  2. Deploy the script as a web app, test it, and fix the common errors with a new version.
  3. Give a customer agent a tool that adds a request, and prevent it from reading other customers' requests.
Section 1 of 4
INTRODUCTION
📋 Note for Students

Today you give the Kestrel Bend sheet a script and give the customer agent, Kestrel Bend Seat Check from the last class, a tool that writes a booking request into the sheet. This page calls the agent Seat Check. The office agent, which helps the manager decide, comes in the next class.

At Kestrel Bend, a customer asks Seat Check for four seats on the sunset paddle. Seat Check cannot promise them, because the manager decides every booking. So Seat Check writes the request in the business's sheet, and in the next class an office agent helps the manager decide. Today you build the sheet's script and the customer side.

The system has four parts. Today you build the first two, the customer agent and the Requests tab, and the script that connects them.

  1. The customer agent, Seat Check, reads the Trips tab and adds each request as a pending row in the Requests tab.
  2. The Requests tab holds one row per request, with its status and the manager's note.
  3. The office agent lists the requests, checks the seats and the weather, and records the manager's decision.
  4. The manager is the person who approves or declines every request and updates the seats.

Seat Check can add a request, and it does not have a tool for reading requests. Only the office agent can read them, so one customer never sees another customer's booking.

Class material
The script prompt
Write a Google Apps Script for a Google Sheet that two Hokie AI agents call through API Calls. Follow these rules exactly.

The sheet has a tab named Requests. Row 1 holds the column names. Read the column names from row 1, so the script works whatever the other columns are. Four of the columns are always there: request_id, time, status and manager_note.

At the top, put the office key in a constant named OFFICE_KEY with the value otter-office-2741.

Write one function named doGet(e). First, open the Requests tab. If the sheet has no tab named Requests, reply with ok false and the error no tab named Requests in this sheet, and stop. If no action was sent, reply with ok false and the error no action in the address, add ?action=add after /exec, and change nothing. Otherwise the function reads the values in e.parameter and does one of three things, depending on the value of action.

1. action is add. Add a new row at the bottom of the Requests tab. Fill every column whose name matches the name of a value that was sent, and leave the other columns empty. Set request_id in two lines of code. In the first line, add 100 to the number of rows in the tab before the new row is added, and keep the result as a number. In the second line, put the letter R in front of that number. A tab with three rows gives R103, never R3100, R1003 or R3. Set time to the current date and time, and status to pending, whatever was sent. Reply with ok true, the request_id and the status.

2. action is list. Do this only when key equals OFFICE_KEY. Reply with ok true and a list named requests that holds every row after row 1, each as a record of column name and value. If a status was sent, include only the rows with that status.

3. action is decide. Do this only when key equals OFFICE_KEY. Find the row whose request_id equals the request_id that was sent. Write the status that was sent in its status column, and the manager_note that was sent in its manager_note column, or empty text if no manager_note was sent. Reply with ok true, the request_id and the status. If no row matches, reply with ok false and the error no request with that request_id.

If key is missing or wrong for list or decide, reply with ok false and the error office key missing or wrong, and change nothing. For any other action, reply with ok false and the error unknown action.

Send every reply as JSON with ContentService and the JSON MIME type, through a small helper function named reply.

At the end of every line of code, write a short comment in plain English that says what the line does, for a reader who has never programmed. Give the whole script in one code block, with nothing after it.
Paste it into a new regular Hokie AI thread. Change nothing. Use the Copy button. Do NOT copy by highlighting the text.

Step 3, the script in your sheet.

  1. In Hokie AI, click the copy button at the top of the code block. Do NOT copy by highlighting the text, because that also copies the word javascript.

Step 4, the deployment.

  1. Click the blue Deploy button, then New deployment.
  2. Next to Select type, click the gear and choose Web app.
  3. In Description, type the name from the box below.
  4. Set Execute as to Me, and Who has access to Anyone.

After you change the script, deploy a new version. A new version keeps your /exec address, so every tool that uses the address keeps working. A New deployment would give you a new address, so use Manage deployments for every fix.

  1. In Apps Script, make the change and press Ctrl+S (Command+S on a Mac). Wait until the save finishes.
  2. Click Deploy, then Manage deployments.
  3. Click the pencil next to your deployment.
  4. Under Version, choose New version.
  5. In Description, type the name from the box below, Kestrel Bend requests v2. Use v3 for the next version, and so on.
  6. Leave Execute as and Who has access as they are, unless the table of error messages says to change one.
  7. Click Deploy, and run the test again in the private window.

If you only renamed the tab, you do not need a new version. Run the test again.

Class material
The Seat Check instructions
You are Kestrel Bend Seat Check, the customer agent for Kestrel Bend Outfitters, a made up river outfitter on the New River used for a class at Virginia Tech.

When someone asks about trips, dates, start times, prices, minimum ages or seats left, call read_trips first and answer only from the rows you receive. A trip with 0 seats left is full.

When a customer wants to book, call read_trips to check that the trip has enough seats left. Then collect the customer's name, the trip_id and the number of people, and repeat them back. When the customer says yes, call add_request in that same reply, once. Give the customer the request_id you receive and say that the office confirms every request by phone. Never say that a trip is booked.

You cannot see other customers' requests. If someone asks about another person's booking, say that you can only help with their own new request. Keep replies short.

For reading
What add_request sends
What add_request sends, field by field

action      Always the word add. The script adds a new row when it receives add. The enum allows only that one value.
name        The customer's name. The script writes it in the name column.
trip_id     Which trip, such as KB104. The agent takes it from read_trips, and the script writes it in the trip_id column.
people      How many people, as a whole number (integer). The script writes it in the people column.
required    The agent may not call add_request until it has all four values.

add_request does not send the office key, so the customer agent can add a request and cannot list or decide requests.
