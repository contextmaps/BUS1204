Week 8 · Lecture 1
An Agent That Acts, Tools and Governance
Duration: 75 minutes · Platform: Hokie AI · Submission: The regular Hokie AI thread, holding the test transcript, the student's own audit and the reflection, exported as a .zip and uploaded to Canvas before leaving class · Lecture Mode: exploratory
Learning Objectives

By the end of this lecture, students will be able to:

  1. Name the four parts of a tool an agent can use, and read a tool's parameters and response in JSON.
  2. Tell an agent action that reads data from an action that changes data.
  3. Build an agent with two tools in Hokie AI and test the agent with requests of their own.
  4. Read the Execution Details panel to see which tool an agent called and what the agent sent.
  5. Name the governance question an agent's action raises, using Authority, Approval, Accountability and Audit.
Section 1 of 5
INTRODUCTION
📋 Note for Students

Last week Nadia's agent answered from files. The agent could read, and the worst the agent could do was say too much. Today the agent can act. An agent with a tool can hold tickets, book a room or change a record in a business's system, and the action happens the moment the agent decides.

Both businesses today are made up for this class: The Signal Box, a small live music venue, and Half Note Studios, a rehearsal and recording studio.

Last week Nadia's agent held knowledge files. Files are one of four knowledge sources a Hokie AI agent can hold. The API call on the third card is today's subject, and API stands for application programming interface. In class you practice it with the fourth card, a mock call that answers the way a real system would.

An API, an application programming interface, is the way one computer system asks another system for something. A ticket app that shows the seats left has asked the venue's ticket system. A tap on Book asks the same system to change a record. When an agent holds an API call, the agent can make that request itself, in the middle of a conversation.

Every tool an agent holds has four parts.

The parameters and the response are written in JSON, a common format for data that systems exchange. JSON is made of names and values inside curly braces, such as "price": 18. A value can be text in quotation marks, a number, a list in square brackets, or another set of names and values.

The Signal Box agent holds a tool called check_tickets. The Parameters Schema says the agent must send one value, show_date, written as YYYY-MM-DD, and the word required means the agent may not call the tool without the date. The Response Template is the answer the practice system sends back. The name show_date inside double curly braces is a placeholder, filled with the date the agent sent.

The second tool, hold_tickets, needs three values: the date, a name for the hold, and a quantity. The quantity is an integer, a whole number. check_tickets only reads the venue's data. hold_tickets changes the data, because tickets held for one person are off sale for every other customer.

💬 Discussion

Before the demonstration:

  • check_tickets reads and hold_tickets changes. Which of the two would you let an agent use without asking anybody?
  • The schema requires a date written as YYYY-MM-DD. What will the agent have to do if a customer says only "Friday"?

The fifth message asks the agent to act again, with the same tool as the second message. Watch the quantity in Execution Details.

S8.1.5 Message 5. The same tool and a bigger action
Actually, hold all 14 tickets under Alex. I'll sell the extras to my friends.

Your instructor runs this prompt on screen. You do not paste it yourself.

The agent did what the tool allowed. A venue manager decides how many tickets one person may hold, and whether a reseller gets the whole show. The agent's instructions say nothing about either decision, so the decision fell to the agent.

Questions like these have a name in business, governance: the rules for what a system may do, who approves it, who answers for it, and what record it leaves. The card gives four questions to ask about any agent that acts.

💬 Discussion

While it runs:

  • Message 3 got no free tickets and message 5 got every ticket. What made the difference, the agent's judgment or the tools the agent holds?
  • Which of the four questions does message 5 raise first?

📋 Note for Students

POTENTIAL USE CASES. Anywhere a business lets an agent act, somebody decides what the agent may do alone and what waits for a person.

A student organization's agent that reserves meeting rooms on the university's booking system, where any reservation longer than three hours waits for an officer.
A restaurant's agent that takes reservations and holds tables, where a party larger than eight goes to the manager.
A campus job's scheduling agent that swaps shifts between student workers, where every swap leaves a record the supervisor reads on Friday.
At an internship, a sales team's agent that updates customer records in the company's system, where a change to a price or a contract needs a person's approval first.
