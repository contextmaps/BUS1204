Week 9 · Lecture 2
A Pricing Script as an Agent's Tool
Duration: 75 minutes · Platform: Hokie AI · Submission: The regular Hokie AI thread, holding the student's audit and the reflection, exported as a .zip and uploaded to Canvas before leaving class · Lecture Mode: consolidation
Learning Objectives

By the end of this lecture, students will be able to:

  1. Tell a rule an agent applies from its instructions from a rule an agent runs as a script.
  2. Describe how Hokie AI turns business rules written in plain words into a Python script, and how a script becomes a knowledge source that Code Interpreter runs.
  3. Add a live date tool and a script to an agent, and read in Tool Calls which tools gathered the script's inputs.
  4. Check one line of a computed quote by hand against the rules it came from.
  5. Decide which rules belong in a script and which instructions stay with the agent, and who approves a change to each.

INTRODUCTION
📋 Note for Students

On Tuesday your concierge looked things up and reported them. The only calculation was turning dollars into euros. Today the concierge prices a stay, with the inn's own pricing rules, and the rules decide the price every time.

Foxglove Inn is the same made up inn as Tuesday, and you extend the concierge you built then.

Foxglove Inn prices a night three ways, and four rules then change the total. The cards hold the rules, written as the inn's owner would write them.

A rule like these can live in three places. Written in the agent's instructions, it is read and applied again on every request. Written as a script, it is a small program the agent runs with Code Interpreter, and it runs the same way every time.

The lead time rule counts the days from today to the arrival. On Tuesday today's date was typed into the instructions. Today a fifth API Call, get_current_time, asks timeapi.io for the date, so the concierge reads the real date every time it needs one.

S9.2.1 Hokie AI writes the script
Write a Python script named quote_stay.py for Foxglove Inn, a 14 room boutique inn in Blacksburg, Virginia. The script holds the inn's pricing rules, so a concierge agent can run it with Code Interpreter. Use only the Python standard library. The script defines one function, quote_stay, with these inputs: room_type, arrival_date as YYYY-MM-DD, nights, today_date as YYYY-MM-DD, home_game_dates as a list of YYYY-MM-DD dates, rain_chance as a dictionary from YYYY-MM-DD dates to a percent from 0 to 100 for the dates the forecast covers, currency as a three letter code, and rate as the number of that currency per US dollar. The rules, in this order. 1. Base rate per night: Queen Room 139 dollars, King Room 159 dollars, Two-Room Suite 249 dollars. 2. Each night is the date of that night. A night is a game night when its date is a home game date or the day before one. A game night costs 1.6 times the base rate. 3. A Friday or Saturday night that is not a game night costs 1.2 times the base rate. 4. Add up the nights to get the room subtotal. 5. Lead time is the number of days from today_date to arrival_date. If it is 7 days or fewer, add 10 percent to the subtotal. If it is 60 days or more, take 10 percent off. 6. If the stay is 3 nights or more, take 8 percent off the result of step 5. 7. Round the US dollar total to cents. 8. Convert the total with the rate. Round to a whole number for JPY, KRW, HUF and ISK, and to two decimals for every other currency. 9. Package. Look up the rain chance for each night's date. If fewer than half of the nights have a forecast, the package is "no recommendation, the forecast does not reach these dates". Otherwise, if more than half of the forecast nights have a rain chance of 60 or more, recommend the Rainy Day Package, and if not, the Trail Package. Before the quote, print every input on its own line, so a reader can see exactly what went in. Then print each night with its date, weekday, the rule that set its price, and its price; then the subtotal, the lead time adjustment, the length of stay adjustment, the US dollar total, the total in the currency, and the package with the reason. Return the same numbers in a dictionary. At the bottom, under if __name__ == "__main__":, run one example: a King Room arriving 2026-11-13 for 3 nights, today 2026-10-22, home game dates ["2026-11-14"], rain_chance {} , currency EUR, rate 0.89.

Your instructor runs this prompt on screen. You do not paste it yourself.

Your instructor saves the script and runs its example. The checked answer is a total of $614.38, two game nights at $254.40 and a Sunday at $159.00 less 8 percent, and 546.80 euros at a rate of 0.89. The script then goes on the concierge as a knowledge file, beside a paragraph in the instructions that says when to run it and which tools gather its inputs.

  • The script holds the prices, and the instructions still say which tools gather the inputs. Which of the two would you check first if a quote looked wrong?

Four minutes, both directions.

📋 Note for Students

POTENTIAL USE CASES. Anywhere a business has rules that set a number, the rules can live in a script an agent runs, and a person approves every change to it.

A campus bookstore's agent that quotes a textbook bundle with the store's discount rules for course packs and returns.
A student organization's agent that prices an event ticket by date, group size and member status, from the treasurer's script.
A landscaping company's agent that quotes a job from square footage, a season and a travel distance, where the owner changes the rates once a year.
At an internship, a sales team's agent that prices a renewal with the company's discount bands, where finance approves every change to the bands.
